# 클립 100개에서도 부드러운 타임라인 만들기 (줌·가상화·자동 스크롤)

## 문제 상황

2주차 완료 기준은 "클립 100개 배치 상태에서도 드래그가 부드럽다"였다. 줌을 넣으면 내용 폭이
수십만 px까지 커질 수 있다(10분 × 1000px/s = 60만 px). 클립과 눈금을 모두 DOM으로 그리면 줌인 상태에서
눈금만 수천 개가 되고, 드래그할 때마다 트랙의 클립 전체가 다시 렌더링되는 구조였다.

## 시도와 설계

1. **기본 스크롤을 유지하고 "렌더링할 시간 범위"만 계산한다.**
   transform으로 스크롤을 직접 구현하면 트랙패드 관성·접근성을 다시 만들어야 한다. 대신 `scrollLeft`와 화면 폭으로
   `renderTimeRange()`를 계산하고, 그 범위에 걸치는 클립·눈금만 그린다.
2. **범위를 덩어리 단위로 맞춘다.** 보이는 영역 양쪽으로 화면 1개 폭씩 여유를 두고, 경계를 화면 폭 절반 단위로 내림/올림한다.
   스크롤 이벤트마다 범위를 계산하지만 값이 같으면 `setState`가 이전 객체를 유지해 리렌더가 일어나지 않는다.
   scroll 이벤트는 브라우저가 프레임당 한 번만 보내므로 별도의 rAF 조절도 필요 없었다.
3. **끌고 있는 클립은 범위 밖이어도 그린다.** 자동 스크롤로 원래 위치가 화면 밖으로 나가도 그 요소가 사라지면
   포인터 캡처가 끊겨 드래그가 중단된다.
4. **드래그 좌표를 "시작점 대비 이동량"에서 "내용 영역 기준 시각"으로 바꿨다.** 잡은 지점의 시간 오프셋(`grabOffset`)을 저장하고
   `pointerTime(content, clientX) - grabOffset`으로 위치를 계산한다. 자동 스크롤 중 포인터가 멈춰 있어도 스크롤된 만큼 클립이 따라온다.
5. **`ClipView`를 `React.memo`로 감싸고 에셋 조회를 Map으로 바꿨다.** 드래그 대상 트랙이 다시 그려져도 다른 클립은 건너뛴다.
6. **줌 기준점 고정.** `scrollLeftForAnchor()`로 줌 후 스크롤 위치를 미리 계산해 두고, 배율이 바뀐 뒤 레이아웃 효과에서 적용한다.

## 측정 (Chromium headless, 개발 빌드, 1440×860)

React `Profiler`(개발 모드)와 `PerformanceObserver('longtask')`, rAF 간격으로 측정했다.
클립 100개(V1 영상 60개, V2 이미지 40개, 약 3분)에서 클립 하나를 60번의 포인터 이동으로 끌었다.

| 상황                              | DOM 클립 수 | rAF 간격 p95 | 50ms 이상 작업 | React 커밋당 렌더 (평균 / p95 / 최대) |
| --------------------------------- | ----------- | ------------ | -------------- | ------------------------------------- |
| 50px/s (가상화 동작)              | 32 / 100    | 16.7ms       | 0              | 1.01 / 1.3 / 5.5ms                    |
| 전체 보기 (100개 모두 표시, 최악) | 100 / 100   | 16.8ms       | 0              | 0.60 / 0.6 / 6.4ms                    |

- 포인터 이동 60번에 React 커밋 61번: 이동마다 한 번, 대상 트랙과 끌리는 클립만 다시 그려진다.
- 휠 줌(6.9 → 51.1px/s) 전후 포인터 아래 시각: 86.705s → 86.716s (1px 미만 오차).
- 자동 스크롤: 오른쪽 가장자리에서 1초 유지 시 약 1080px 스크롤.

## 배운 점

- 가상화는 "보이는 것만"이 아니라 **"언제 다시 계산할지"**가 핵심이다. 범위를 덩어리로 맞추는 것만으로 스크롤 중 리렌더가 사라진다.
- 드래그 중인 요소를 가상화로 지우면 포인터 캡처가 끊긴다. 상호작용 중인 요소는 예외로 고정해야 한다.
- 화면 좌표의 "차이"로 위치를 계산하면 스크롤·줌이 끼어드는 순간 틀어진다. 의미 있는 단위(시간)로 기준을 저장하자.
