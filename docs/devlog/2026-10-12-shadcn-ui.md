# shadcn/ui 도입: 레지스트리 없이 설치하고, 복사한 컴포넌트의 접근성 고치기

## 문제 상황

MVP 화면은 Tailwind 팔레트 색(`neutral-800`, `sky-600` …)을 컴포넌트마다 직접 써서 만들었다. 버튼 스타일 문자열이
여러 파일에 반복되고, 모달·확인창·슬라이더는 직접 만든 것이거나 네이티브(`window.confirm`, `<input type="range">`)였다.
포트폴리오로서 일관된 디자인 시스템을 갖추기 위해 shadcn/ui를 적용했다. 그 과정에서 세 가지 문제를 만났다.

1. **CLI가 동작하지 않았다.** `shadcn init`이 `ui.shadcn.com` 레지스트리에 요청하는데, 작업 환경의 네트워크 정책이
   이 호스트를 막고 있었다 (npm 레지스트리와 GitHub 원본만 열려 있음).
2. **복사해 온 컴포넌트에 이 편집기와 맞지 않는 부분이 있었다.**
   - 비활성 버튼이 `pointer-events-none`이라 hover가 없어 "왜 비활성인지" 알려주는 `title` 툴팁이 안 보인다.
     편집기는 내보내기·자르기·SRT 저장·실행 취소 버튼에 비활성 이유를 툴팁으로 알려 준다.
   - `Progress`가 `value`를 Radix Root에 넘기지 않아 `aria-valuenow`가 빠진다. 기존 테스트
     (`progressbar`의 `aria-valuenow`가 25인지)가 바로 잡아냈다.
   - `Slider`의 `aria-label`이 Root(`span`)에 붙고, 실제 `role="slider"`인 thumb에는 이름이 없다.
3. **테스트가 깨졌다.** Radix 모달은 열려 있는 동안 배경에 `aria-hidden`을 걸어 `getByRole`이 배경 버튼을 찾지 못하고,
   Radix 슬라이더는 `change` 이벤트가 아니라 키보드·포인터로 움직이며, jsdom에 없는 `ResizeObserver`를 쓴다.

## 시도한 방법

- 이전 버전 CLI, 다른 CDN(jsDelivr·unpkg)도 같은 정책으로 막혔다.
- 비활성 버튼을 `span`으로 감싸 툴팁을 거는 방법은 버튼마다 감싸야 하고, 테스트가 확인하는 버튼 자체의 `title`과 중복된다.

## 최종 해결책

- **수동 설치** (shadcn 문서의 Manual Installation과 같은 결과): `raw.githubusercontent.com`에서 new-york-v4 컴포넌트 소스를
  받아 `src/components/ui/`에 두고, 의존성(`radix-ui`, `class-variance-authority`, `clsx`, `tailwind-merge`,
  `lucide-react`, `tw-animate-css`)은 npm으로 설치했다. `components.json`도 직접 작성해, 네트워크가 열린 환경에서는
  `shadcn add`를 그대로 쓸 수 있다.
- **소스를 소유하니 고치면 된다.** shadcn은 패키지가 아니라 "내 코드에 복사한 컴포넌트"이므로 편집기에 맞게 고치고
  `// 편집기 수정:` 주석으로 원본과 다른 곳을 표시했다.
  - Button: `disabled:pointer-events-none` → `disabled:cursor-not-allowed`, variant의 hover는 `not-disabled:hover:`로
  - Progress: Root에 `value` 전달
  - Slider: `aria-label`/`aria-labelledby`를 thumb으로 전달 (인스펙터는 `<Label id>` + `aria-labelledby`로 연결)
  - Alert: 오류는 아니지만 주의가 필요한 안내용 `warning` variant 추가 (호환성 안내, 일부 자막을 건너뛴 경우, VP9 내보내기 안내)
- **색은 토큰으로만.** `src/index.css`에 shadcn 토큰(neutral 베이스 + 파란 primary)과 편집기 고유 토큰
  (`panel`, `warning`, `clip`, `text-item`, `selection`, `playhead`)을 정의하고, 컴포넌트의 팔레트 색을 모두 토큰으로 바꿨다.
- **테스트는 동작에 맞게.** 모달 중 배경 버튼은 `{ hidden: true }`로 찾고(배경이 보조기기에서 숨겨지는 것이 올바른 동작),
  슬라이더는 키보드(`ArrowRight`, `Home`/`End`)로 조작하며, 테스트 설정에 아무것도 하지 않는 `ResizeObserver`를 넣었다.
  `window.confirm` 대신 `AlertDialog`를 쓰게 되어 테스트도 `alertdialog` 역할로 확인한다.

## 결과

- 테스트 398개, 타입 검사, 린트 모두 통과. 내보내는 중 Esc는 무시되고, 끝난 뒤 Esc로 닫힌다 (브라우저 확인).
- 비용: 첫 화면 JS가 gzip 기준 97KB → 133KB (+36KB, Radix 프리미티브·tailwind-merge·아이콘). mediabunny는 여전히 동적 import.

## 배운 점

- "복사해서 소유한다"는 shadcn의 방식은 버그나 요구사항 차이를 만났을 때 진가가 나온다. 패키지였다면 이슈를 올리고 기다리거나
  래퍼를 덧씌워야 했을 것을, 원본에 주석을 남기고 바로 고칠 수 있었다.
- 그 대신 복사한 코드도 내 코드처럼 검증해야 한다. 접근성 버그 두 개는 기존 테스트가 역할·이름으로 요소를 찾고 있었기 때문에
  잡혔다. `getByRole`로 쓴 테스트는 UI 라이브러리를 바꿀 때 안전망이 된다.
