# 클립 경계에서 끊기지 않는 프리뷰 재생 만들기

## 문제 상황

프리뷰는 `<video>`를 화면에 쓰지 않고 WebCodecs로 디코딩한 프레임을 캔버스에 그린다.
가장 단순한 구현은 매 프레임 "지금 시각의 프레임"을 `getSample(time)`으로 요청하는 것이지만,
이 방식은 매번 가장 가까운 키프레임부터 다시 디코딩하므로 재생 중에는 감당할 수 없다.
또 클립 A가 끝나는 순간 클립 B의 디코딩을 시작하면, 첫 프레임이 나올 때까지 화면이 멈춘다.

## 시도와 설계

1. **탐색과 재생을 다른 경로로 분리했다.**
   - 정지 상태(탐색)는 `renderAt(project, time)`: 정확한 프레임을 비동기로 디코딩해서 그린다.
   - 재생 중에는 `renderPlaying(project, time)`: **동기 함수**로, 이미 디코딩된 프레임만 즉시 그린다.
     rAF 콜백 안에서 디코딩을 기다리지 않는다.
2. **클립마다 순차 디코딩 버퍼(`FrameStream`)를 둔다.** 백그라운드에서 최대 4프레임을 앞서 디코딩하고,
   재생 루프는 `frameAt(time)`으로 "표시 시각 ≤ time인 가장 늦은 프레임"을 꺼낸다. 건너뛴 프레임은 바로 `close()`한다
   (1080p 프레임은 장당 수 MB의 GPU/메모리를 잡는다).
3. **다음 클립은 1초 전부터 미리 디코딩한다.** `findUpcomingClips(project, time, 1s)`로 곧 시작할 클립을 찾아
   스트림을 먼저 만들어 둔다. 경계에 도달했을 때는 이미 첫 프레임이 버퍼에 있다.
4. **프레임이 늦으면 시계를 멈추지 않고 이전 화면을 유지한다.** 검은 화면으로 깜빡이는 것보다 낫고,
   일반 플레이어와 같은 동작이다. 늦은 횟수(`lateTicks`)를 통계로 남겨 품질을 측정할 수 있게 했다.
5. **연속 탐색은 마지막 요청만 처리한다.** 디코딩 중 새 탐색이 오면 대기 플래그만 세우고,
   현재 렌더가 끝나면 최신 위치 하나만 다시 렌더한다.

`PlaybackEngine`은 시계(`now`), `requestFrame`, 렌더러를 주입받도록 만들어
가짜 시계로 재생·일시정지·끝에서 멈춤·탐색 합치기를 단위 테스트했다.

## 결과

Chromium(headless)에서 3초 webm 2개 + 이미지 1개(총 11.1초)를 이어서 재생하며 매 rAF마다
"현재 시각 − 마지막으로 그린 프레임의 시각"을 기록했다.

| 지표                      | 값                       |
| ------------------------- | ------------------------ |
| 재생 틱 수                | 606                      |
| 프레임이 준비되지 않은 틱 | 1 (재생 시작 직후 첫 틱) |
| 최대 화면 지연            | 16.7ms (1 rAF 이하)      |
| 100ms 이상 멈춘 횟수      | 0                        |

클립 경계에서는 A의 마지막 프레임(2967ms) 다음 틱에 바로 B의 첫 프레임(0ms)이 그려졌다.

## 덤: 번들 크기

mediabunny를 그대로 가져오니 JS가 229KB → 608KB(gzip 72 → 172KB)로 늘었다.

- `ALL_FORMATS` 대신 영상 컨테이너(MP4·MOV·WebM·MKV)만 등록 → 480KB
- `await import('mediabunny')`로 첫 영상을 열 때 불러오도록 분리 → **첫 화면 247KB(gzip 78KB)** + 지연 청크 234KB

## 배운 점

- 재생 루프는 "기다리지 않는다"가 핵심이다. 비동기 작업은 루프 밖에서 미리 해 두고, 루프는 준비된 것만 쓴다.
- 품질을 말로 주장하지 말고 측정 지표(늦은 틱, 최대 지연)를 코드에 심어 두면 회귀를 잡기 쉽다.
- TypeScript의 타입 좁히기는 `await` 너머의 상태 변경을 모른다. `while (!this.disposed) { await ...; if (this.disposed) }`가
  "항상 거짓" 린트 에러로 잡혀, 메서드(`isDisposed()`)로 읽도록 바꿨다.
